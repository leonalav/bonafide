## Summary

> **20/97 IPC functions consumed directly by renderer components.**
> **4/4 backend agent commands registered.**
> **All UI surfaces reachable: NO (gaps noted below).**

Specific gaps:

1. **Phase 3 IPC commands not registered in the Rust backend:**
   `review_code`, `search_arxiv`, `get_arxiv_paper`,
   `detect_anomalies`, `query_project_memory`, `write_project_insight`,
   `write_project_dead_end`. These are invoked from `ipc/tauri.ts`
   but are NOT in `tauri::generate_handler![…]`. Calls will fail in a
   real Tauri window. The browser preview returns stubs so it
   doesn't crash.

2. **`ApprovalDialog.tsx` is orphaned.** It is fully implemented
   (T9 — commit `b9d6858`) but no other file imports it. There is no
   consumer watching for thread state transitions to
   `AwaitingApproval` and triggering the dialog. **No approval-gate
   UX exists at runtime today.**

3. **Inspector "Memory" and "Researcher" tabs are absent.** Memory is
   embedded in the Workflow inbox + Composer; Researcher is a
   Composer mode. Renaming the existing tabs would not be required,
   but if the spec calls for dedicated Memory/Researcher surfaces,
   those are missing.

4. **Many agent IPC commands are unused at the component layer.**
   `stopThread`, `checkToolPermission`, all `writeProjectMemory`
   variants, experiment CRUD, scaffold/run-smoke/proposeExperiment —
   none are wired into a component. This is normal scaffolding for
   unfinalised WS groups, but means the T12 "consumed" count is low
   relative to the surface defined.

## Concerns

- `ApprovalDialog` being orphaned is the most user-visible gap: in a
  real Tauri window, an agent thread that enters
  `AwaitingApproval` will silently wait for IPC-driven resume, with
  no UI prompting the user. This blocks the WS5 "approval gate"
  promise end-to-end.
- The Phase 3 IPC gap (`review_code`, etc.) means the new
  `ProposalView` Critic integration (T11) will surface a
  "review failed" state in a real Tauri build until the backend
  handlers are added. Browser preview still works fine.
- The 101 cargo warnings are pre-existing dead code from the WS0-T1
  mock-wipe and were not introduced by T10/T11/T12. They should be
  cleaned up in a dedicated hygiene pass.

## Recommendation

The T10/T11 commitments are stable and meet their stated goals.
T12 surfaces **3 blocking concerns** that should be tracked as
follow-up work:

- **Block A:** wire `ApprovalDialog` into a watcher that observes
  thread state and opens the modal when it transitions to
  `awaiting_approval`.
- **Block B:** register the Phase 3 IPC handlers
  (`review_code`, `search_arxiv`, `get_arxiv_paper`,
  `detect_anomalies`, `query_project_memory`,
  `write_project_insight`, `write_project_dead_end`) in
  `tauri::generate_handler!`.
- **Block C:** decide whether dedicated Inspector tabs for "Memory"
  and "Researcher" are required, or whether the Composer / Workflow
  surfaces are acceptable alternatives per the original spec.
